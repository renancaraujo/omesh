# File spec for O'Mesh:

- filespec version:1B
- mesh:R

(R) "Rectangular mesh":
- (w)width:4b
- (h)height:4b
- positions & control points (nulling for null control points):w*h*V
- colors (nulling for undefined colors):O
- color space:7b
- smoothcolors:1b
- fallback color (optional):1b+{C}
- background color (optional):1b+{C}

(V) Rectangular mesh vertex:
- x:8B
- y:8B
- (n,e,s,w)presence of control points:1B
- north:n{16B}
- east:e{16B}
- south:s{16B}
- west:w{16B}

(O) Rectangular mesh color list:
- (n)length:2B
- color values:n*C

(C) Rectangular mesh vertex color:
- color header (index, colorspace):2B
- color value:J|k

(J) sRGB color value:
- red:1B
- green:1B
- blue:1B
- alpha:1B

(K) display P3 color value:
- red:4B
- green:4B
- blue:4B
- alpha:4B

# Hash

- prefix:"OM:"
- base64url without padding of the whole binary format, zlib (RFC 1950)
  compressed

Decoders read a zlib stream from any writer, since different DEFLATE
implementations compress the same data to different bytes. They verify the
Adler-32 checksum. Streams with a preset dictionary are not supported.

A decoder may accept more than this section describes, such as padding or
another prefix. Such a hash is still not valid.

The Dart encoder writes the same hash on every platform. It never uses the
native zlib: it uses the pure Dart DEFLATE of the archive package, with level
6 and a 32K window. The stream starts with the bytes 78 01, and the DEFLATE
data is what zlib writes at level 6 with memLevel 8. Other encoders do not
have to write the same bytes.
